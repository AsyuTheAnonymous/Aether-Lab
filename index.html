    The Codex

    Short answers to the things that go wrong most.

    Patching

    “Wrong source ROM” — what now?
    • BPS, UPS and xdelta know the exact ROM they were made for. If auto-fix can’t find a match, you have a different dump: another region, revision (v1.0 vs v1.1), or a bad dump.
    • Check the hack’s readme for the expected CRC32/MD5/SHA-1 and paste it into Compare with a checksum under the ROM on the Patch tab.
    • IPS has no checksum, so it will “apply” to anything. If an IPS hack crashes, try the opposite header setting.
    Patching

    Headered vs headerless
    • SNES: a 512-byte copier header (file size ends in …512). Modern hacks want it removed — auto-fix handles it.
    • NES: the 16-byte iNES header is normally kept; patches are made with it.
    • N64: patches expect .z64 order. .v64/.n64 are converted automatically for checksummed patches.
    • Mega Drive: .smd files are interleaved; use “Remove header” to get a plain .bin.
    Patching

    Which format should I share hacks in?
    • BPS — the default choice: checksummed, any size, compact even when data moves.
    • UPS — checksummed and reversible; fine for GBA.
    • IPS — only when a tool demands it. Max 16 MB and no checksum.
    • xdelta — big disc images (PS1/PS2/GameCube). Create those with xdelta3 using -S none so browser patchers can apply them.
    Patching

    Big disc images
    • Everything happens in memory, so files of about 2 GB are the practical ceiling in most browsers (desktop Chrome / Firefox do best).
    • Convert .chd/.rvz/.wbfs/.cso to a plain image first; patch; then re-compress if you like.
    • PS1 PPF patches normally want the raw .bin from your .cue, not an .iso.
    Privacy

    Where do my files go?
    • Nowhere. The page’s security policy blocks every network request (connect-src 'none'), so even a bug couldn’t upload anything.
    • Keys, ROMs and patches live only in this tab’s memory and are released when you close it.
